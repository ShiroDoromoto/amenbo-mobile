# amenbo-plugin-viewer

PC から離れているあいだも、スマートフォンから [**Amenbo**](https://github.com/ShiroDoromoto/amenbo)
のタスクの進み具合を見る。**Amenbo Viewer** のアプリ（iOS / Android）。

Amenbo 本体は外部と通信しない。運営もデータをホスティングしない。**置き場は利用者が持つもの**で、
そこへレコードを片方向に運ぶ。**運ぶのは動いたぶんだけ**で、スマートフォンは自分が読んだ点から先を取る。

## ここに入っているもの

**アプリだけ。** 送り手（PC 側）と Worker は、どちらも [Amenbo 本体](https://github.com/ShiroDoromoto/amenbo)
が持っている——プラグイン機構を畳んで本体の機能にしたときに移した。このリポジトリに残っているのは、
スマートフォンで読む側である。

| | 中身 |
|---|---|
| [`app/`](app/) | スマートフォンアプリ（Flutter。`ios/` と `android/` はこの下に生成される） |
| [`guards/`](guards/) | アプリの外にある検査（いまは CI の集約ジョブの `needs:` 漏れを見る。`make guards` と CI が回す） |

リポジトリ直下は Flutter に渡さない。ビルドはルートの `Makefile` が束ね、実体は `app/Makefile` が持つ。

```
make app      # アプリだけ
make test     # ガード ＋ アプリのテスト
```

## 契約は本体と共有している

レコードの形・暗号の封筒・QR に載せるもの・エンドポイントの仕様は、送り手と分け合っている。
**片側がこのリポジトリに無くなっても、契約を散文で置く場所は作らない**——置けば、どちらを直しても
文書の追従が要り、その漏れは静かに起きる（両方動いていて文書だけが嘘、という形になる）。

このリポジトリ側の契約は、取り込むコードとそれを踏むテストが持つ——`app/lib/` の
`cloudflare_intake.dart` と `record_envelope.dart`、`app/test/` の各本。
**ずれは読んで見つけるのではなく、通して見つける。**

## 経路は1つ

| 経路 | 利用者の手数 |
|---|---|
| 利用者自身の Cloudflare Worker ＋ D1 | Cloudflare のアカウント1つ。**API トークンを1回貼るだけ**で、立てるのは Amenbo 本体 |

一方通行で、運ぶ単位は**レコード1件ずつ**。

**必ず封をする。** 置き先は利用者が借りている場所なので、暗号文しか置かない。鍵はネットワークを
通らず、QR でスマートフォンへ渡る。

置き場が D1 なのは、**1キーの上書きでは答えられないことが2つある**ため——
「この順番から先で何が変わったか」と「この行を忘れろ」。だからスマートフォンが読むのは範囲で、
PC が送るのは動いた行だけになる。

## ドキュメント

**[`app/README.md`](app/README.md) しか無い。** 設計を散文で置く場所を作らないのは契約と同じ理由で、
実装が進むほど文書だけが古くなり、動いているものと食い違ったまま残るからである。
決めた理由は、それが効くコードの隣に書く。

## 名前

| | 名前 |
|---|---|
| リポジトリ | `amenbo-plugin-viewer` |
| アプリ名（ストア表示） | **Amenbo Viewer** |
| バンドル ID / パッケージ名 | `work.amenbo.viewer`（ストアのもの。手元は `.local`、配って試すものは `.dev` が付く→ [app/README.md](app/README.md)） |

大小は、その文字列が**実体か呼び名か**で決まる。機械がその綴りのまま解決するもの——打つコマンド、PATH に載る名前、リポジトリ名、URL、バンドル ID——は小文字の `amenbo`。文章の中で製品を指すときは `Amenbo` / `Amenbo Viewer`。迷ったら「`Amenbo` へ書き換えたら何かが動かなくなるか」を問う。なるなら小文字側で書く。
